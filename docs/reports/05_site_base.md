# Task 05: site base (→ v0.5.0)

## Summary

The site now has everything the real pages will sit on. A stranger can clone the repo, fill four secrets into `.env`,
run `docker compose up -d`, and get the site, its database and RECONSUMΣT.TS's API and relay running together. I
tested exactly that on tsss-server using only the README, and it worked first time. On that stack people can create
an account (email, or Discord/Google/GitHub/Microsoft once configured), protect it with a passkey or two-step
verification, and see real anime from the API on a simple placeholder home page with the three.js wave behind it.
Anything a guest watched in the browser moves into their account when they sign up.

The end-to-end tests drive a real Chromium through every flow: email sign-up with a real verification email, 2FA
(authenticator code and backup code), passkey with a virtual authenticator, guest data reaching the database,
search, health and posters. All 7 pass. The sign-in page and the placeholder home both score **100 for accessibility**
in Lighthouse.

Two things were cut on your call at the start: **AniList and MyAnimeList logins** move to the list-import task, and
the **`/dev/ui` showcase page** wasn't built.

Things to know:
- Social logins (Discord, Google, GitHub, Microsoft) are **only unit-tested**: there's no `.env` with real
  credentials in the repo folder, so I couldn't try a real Discord sign-in.
- The Docker image is **776 MB**. It works, but it's bigger than it should be; there's a slimming idea below.
- The new GHCR package will start **private**. After the tag push, set it to public once.

## What's built

- **App:** Next.js 16.4.6 (App Router, TypeScript 7 strict, `output: "standalone"`, Node runtime only, nothing
  Vercel/Cloudflare-specific), React 19.3, Tailwind 4.3 (CSS-first `@theme`), Biome 2.6, Vitest 5.1, Playwright 1.65,
  Prisma 7.10.1 (not the 8.x RCs) with `@prisma/adapter-pg`, Better Auth 1.7.28, three 0.187, zod 4.6, Node 26,
  pnpm 11.13. Each version was checked on npm on 2026-11-24.
- **Config** (`src/config/`): every setting comes from env and is parsed with zod. One error lists every missing or
  invalid variable (including half-configured providers and SMTP without a sender). The module is `server-only`;
  client components get only `publicConfig()` (name, URL, description, logo, Discord, analytics). It's read at
  request time, so `next build` needs **no env** and one image fits everyone.
- **Client IP** (`server/client-ip.mjs`): Next.js keeps a client-sent `X-Forwarded-For` and drops the socket
  address. So the image preloads a small hook (`node --import`) that works out the viewer's IP with the same rule as
  RECONSUMΣT.TS (forwarded header only from `TRUSTED_PROXIES`, rightmost untrusted hop) and writes it to
  `x-site-client-ip`, always overwriting whatever the client sent. Better Auth's rate limits and sessions read that
  header, and so does `clientIp()` for the streams route in task 06.
- **Database:** Better Auth tables generated by its CLI (`pnpm auth:schema`, via `scripts/`), plus `WatchProgress`,
  `ListEntry` and `UserSettings` (JSON prefs), all cascading on user delete. One migration is committed; the container
  runs `prisma migrate deploy` on start.
- **Design system** (`src/app/globals.css`, `src/components/ui/`): the mockup tokens as `@theme` (colours, radii,
  shadows, durations, easings, rise/pop/shimmer animations), Syne + Inter via `next/font` (downloaded at build time,
  no runtime Google calls), and a global reduced-motion rule that follows the OS unless the user picks otherwise
  (`<html data-motion>`, saved in a cookie and in `UserSettings`). Components: Button, IconButton (label = tooltip +
  accessible name), Input (label, hint, inline error with `aria-describedby`), Select, Switch, Badge (SUB filled / DUB
  outlined), Card, Skeleton + SkeletonGroup (`aria-busy`), Tabs, Menu, Dialog / Sheet, Tooltip, Toast with Undo
  (5 s), Avatar, Alert. Targets are at least 44 px and focus rings are always visible.
- **Shell:** sticky blurred header (logo or `SITE_NAME`, nav, search, account menu or "Sign in"), footer (logo +
  Discord when set + source code link), back-to-top, toasts, skip-to-content link.
- **Header search:** a WAI-ARIA combobox (↑ ↓ / Enter / Esc, Ctrl K), 200 ms debounce, abortable,
  loading/empty/error states, thumbnails through `next/image`, backed by `GET /api/search`. Enter without a pick goes
  to `/search` (a simple results stub); a pick goes to `/anime/:id` (a stub page so links don't 404 until task 06).
- **`Waves`:** a port of `Waves.dc.html`. One `Points` + `BufferGeometry` (140×20 = 2 800 points), `three` loaded
  only in the browser, `ResizeObserver`, the loop stops off-screen or in a hidden tab, one still frame under reduced
  motion, everything disposed on unmount, no WebGL → empty canvas.
- **Accounts:** sign in, sign up, forgot/reset password, verify email, 2FA challenge (app / backup code / email code),
  all `noindex`, with loading, error and success states. Settings: **Account** (name, remove photo with Undo, email
  change, motion preference), **Security** (password change with "sign out everywhere else", 2FA on/off with QR +
  manual key, backup codes shown once with copy/download, regenerate; passkeys add/rename/delete; linked accounts;
  active sessions with per-session and "everywhere else" sign-out), **Delete account** (password if any + type
  DELETE; cascades all data). Emails are plain text over nodemailer: verification, reset, 2FA code, optional new
  sign-in. Breached-password check is on by default. Rate limits are stored in the database (`rateLimit` table).
  Cookies are `Secure` when `SITE_URL` is https.
- **Guests:** progress, list and settings live in `localStorage` (`guest:v1`), in the table shapes. After any sign-in
  (password, social, passkey) `GuestMerge` sends them to the `mergeGuestData` server action, which validates with zod
  (size-capped), merges (newest `updatedAt` wins; something completed never goes back to not completed; settings
  merge key by key), upserts in one transaction, then clears locally. Unit-tested and e2e-tested down to the rows.
- **RECONSUMΣT.TS client** (`src/server/reconsumet.ts`): `@reconsumet/client` 0.4.2 from npm, 8 s timeout, errors
  mapped to `down` / `not_found` / `rate_limited` / `bad_request`, Next data cache matched to the API (search 5 min,
  anime 1 h, episodes 10 min, streams never). The key never leaves the server.
- **`GET /api/health`:** `{ ok, version, database, reconsumet: { ok, version } }`. It returns 200 while the database
  is up (so a RECONSUMΣT.TS outage doesn't mark the container unhealthy, but `ok` turns false), and 503 when the
  database is down.
- **Placeholder home:** hero with `Waves`, a "Picks" row from `HOME_ANILIST_IDS` (staggered entrances, skeletons
  while loading), and a friendly message if the API is unreachable.
- **Security headers** (`src/proxy.ts`): per-request nonce CSP (`script-src 'self' 'nonce-…' 'strict-dynamic'`;
  img from self/data/blob + logo + avatar CDNs of *enabled* providers; `connect-src`/`media-src` add
  `RELAY_PUBLIC_URL`; `frame-ancestors 'none'`; `form-action 'self'`; `object-src 'none'`;
  `upgrade-insecure-requests` + HSTS on https), `Referrer-Policy`, `X-Content-Type-Options`, `X-Frame-Options`,
  `Permissions-Policy`. **`IMAGE_HOSTS` is enforced at runtime here**: `next.config` has to bake `remotePatterns` in
  at build time, so it allows any https host and the proxy refuses `/_next/image` for anything not listed. That keeps
  the image optimizer from becoming an open proxy and lets one image work with any config. CSRF: Better Auth's own
  origin checks (`SITE_URL` is the only trusted origin).
- **Docker:** a multi-stage `node:26-bookworm-slim` image, standalone output, non-root `node` user, healthcheck on
  `/api/health`, `prisma migrate deploy` then `node --import ./client-ip.mjs server.js`. Nothing is CPU-tuned.
- **Compose:** `site`, **one Postgres with two databases** (an init script adds `reconsumet`; the API image is
  happy with a plain database, and `pg_trgm` is a trusted extension the owner can create), RECONSUMΣT.TS `api` +
  `relay` pinned to **0.4.2**, `RECONSUMET_API_KEY` → `API_BOOTSTRAP_KEY`, `RELAY_ALLOWED_ORIGINS=SITE_URL`.
  Optional `caddy` profile (site + relay domains) and `mail` profile (Mailpit). The API and Postgres aren't
  published. Extra RECONSUMΣT.TS settings go in an optional `reconsumet.env`. Required for a first run: exactly the
  four secrets.
- **CI:** `ci.yml` (install, lint, typecheck, unit tests, build, amd64 Docker build) and `release.yml` (`v*` →
  `ghcr.io/thesupersupersigma/thesupersuperanime:<version>` + `:latest`, amd64 + arm64 under QEMU). Not triggered.
- **Docs:** `docs/self-hosting.md`, `docs/auth.md`, `e2e/README.md`, README with screenshots, a fully commented
  `.env.example`.

## Library choices

- **Radix UI** (the `radix-ui` 1.8 package) over React Aria. It's one unstyled package that covers 9 of the 10
  primitives we need (Dialog, DropdownMenu, Tabs, Tooltip, Toast, Switch, Select, Avatar, Slot), it's lighter, and
  it fits Tailwind styling directly. The one thing it lacks, a combobox, is a single small hand-written component
  (the search box) following the WAI-ARIA pattern. React Aria's combobox would have meant a second library for that
  alone.
- **nodemailer** for SMTP (standard, no service lock-in). **qrcode** for the 2FA QR as a `data:` URL (allowed by the
  CSP). **lucide-react** icons. Social buttons are text-only, since lucide no longer ships brand logos and no emoji
  icons are allowed.
- **otpauth** and **pg** are only used by the e2e tests (pg is also Prisma's driver).

## Which sign-ins 2FA applies to

Checked in Better Auth 1.7.28's code (`plugins/two-factor/index.mjs`): the 2FA hook runs only after `/sign-in/email`,
`/sign-in/username` and `/sign-in/phone-number`. On this site that means:

- **Email + password: yes.**
- **Passkey: no.** A passkey is already two factors.
- **Discord / Google / GitHub / Microsoft: no.** The provider's own 2FA covers it.
- **Email-confirmation link after sign-up: no.** It auto-signs-in.

So the 2FA section only shows for accounts that have a password, and the docs say so. Details: 10 backup codes, and
the account locks 15 min after 10 wrong codes.

## Turning on each login for your own site

Your own values go only in your private `.env` on the server (below, `SITE_URL` stands for your real address):

1. **Basics:** `SITE_URL`, `SITE_NAME`, `DISCORD_INVITE_URL`, `RELAY_PUBLIC_URL`, and `TRUSTED_PROXIES` for your
   Coolify/Cloudflare path (with Cloudflare Tunnel: `CLIENT_IP_HEADER=CF-Connecting-IP`).
2. **Email:** your SMTP values (`SMTP_HOST/PORT/USER/PASS/FROM`). That turns on email sign-up with verification,
   reset and email 2FA codes.
3. **Discord:** Developer Portal → your app → OAuth2 → Redirects → `SITE_URL/api/auth/callback/discord`
   → copy Client ID + reset/copy secret → `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`.
4. **Google:** Cloud Console → Google Auth Platform (External, publish) → Clients → Web → origin
   `SITE_URL`, redirect `SITE_URL/api/auth/callback/google` → `GOOGLE_CLIENT_ID/SECRET`.
5. **GitHub:** Settings → Developer settings → OAuth Apps → New → callback `SITE_URL/api/auth/callback/github` →
   `GITHUB_CLIENT_ID/SECRET`.
6. **Microsoft:** Entra → App registrations → New (any org directory + personal accounts) → Web redirect
   `SITE_URL/api/auth/callback/microsoft` → Certificates & secrets → new secret (copy the **Value**, set a calendar reminder
   before it expires) → `MICROSOFT_CLIENT_ID/SECRET`.
7. `docker compose up -d` (or redeploy in Coolify). Check the sign-in page shows the buttons, then try each one.

Full steps: `docs/auth.md`.

  breaks the URL (about 1 in 3 generated passwords). Suggest `-hex 32` there, as this repo now does.

## For task 06

- **Streams:** call `reconsumet.streams(id, ep, { audio, viewerIp: await clientIp() ?? undefined })` from a route
  handler; `clientIp()` is `null` under `pnpm dev`. The CSP already allows `RELAY_PUBLIC_URL` for media/connect and
  `blob:` workers (hls.js / JASSUB). JASSUB's WASM may need `'wasm-unsafe-eval'` in `script-src`: add it in
  `buildCsp`.
- `/anime/[id]` and `/search` are stubs to replace. Add Browse/Schedule to `NAV` in `header.tsx`.
- Guest data: write through `readGuest`/`writeGuest` in `src/lib/guest.ts` (same shapes as the tables); signed-in
  users go to the tables. `prefs` already has autoplay, autoskip, audio, subtitleSize, reducedMotion, timeZone.
- Use `prefersReducedMotion()` (`src/lib/motion.ts`) for JS animations: it honours the user override as well as the OS.
- `/api/search` has no per-visitor rate limit of its own: it relies on the debounce, a 60 s browser cache and the
  API's per-key limit. Worth adding a small per-IP limiter if the search page makes heavier calls.
- **Image size (776 MB):** most of it is the Prisma CLI kept for `migrate deploy` plus its engines. Option: apply
  the committed SQL migrations with a 30-line runner using `pg` (already bundled) and drop the CLI from the runtime
  image.
- Next's build rewrites `tsconfig.json` formatting and Biome formats it back (harmless churn); exclude
  `tsconfig.json` from Biome's formatter if it gets annoying.
- `pnpm start` (`next start` with the preload) is untested; Docker uses `server.js` directly.
